# F054 · A project overlay that is an older package copy gets named

## Outcome

When a project's `.agents/limen/worker.md`, `reviewer.md`, `communication.md`, or `AGENTS.md` is byte-identical to an earlier revision of the package template, the owner is told so at `limen init` and at every coordinator turn's drift section, with the two dates. Today only a copy identical to the current package is named; a copy of last month's text counts as a deliberate overlay and silently keeps every later package fix away from the project. Alice ran three days of review churn on a reviewer prompt the package had already replaced.

## Scope

- Add a third drift kind, `stale`, to `hook/inherit.ts`: the project file equals some past revision of the package source. Resolve past revisions from the package clone's Git history first (`git log` and `git show` on the template path), and from a shipped `templates/.history/<file>` hash list when the package has no `.git`.
- The drift text names the revision date the copy matches and the date the package last changed that file, and says what deleting the file would do.
- `limen init` prints the same line; `limen init --drop-leftovers` keeps treating only byte-identical current copies as leftovers.
- Cache the history lookup per process so a long session does not re-run Git each turn.

## Out of scope

- Deleting or rewriting any overlay; the owner decides.
- Diffing an overlay against the package or merging changes.
- Overlays of files outside the tracked four.

## Acceptance

- With a temporary Git repository as the package root holding two revisions of `templates/reviewer.md`, a project file equal to the first revision is reported `stale (package text as of <date 1>; package changed <date 2>)`; one equal to the second is `leftover`; one differing from both is `overlay`.
- With no `.git` at the package root, the shipped hash list produces the same three answers.
- The drift section of the per-turn note and the `limen init` output carry the line; the structure test lists the new history file.
- The hook suite passes.

## Notes

The history list is regenerated by the same script that checks the templates, so it cannot fall behind a template edit.
