Alice / whole map   /   Journey

Send a message. Follow the responsibility.

  1. The window submits.

    Typed RuntimeClient sends the input. The projector renders journal facts and decorates them with live progress.

  2. One envelope crosses Tauri.

    The runtime-request route calls Runtime. This is a message path; account requests take the host's account branch.

  3. The bounded loop takes work.

    Read current authored identity. Use work rows to schedule. Dispatch under Grants, deadlines and budgets.

  4. Injected adapters act.

    Models/services speak concrete protocols; Code uses the contained runner. Neither owns a second work queue.

  5. History remains; clients reread.

    Journal intent/results explain durable actions. Live chunks are disposable. A reconnect rereads authority, not a notification log.

Why the boundary matters

A window can leave without taking the work with it.

Client subscription lifetime and runtime lifetime are different owners. Explicit runtime stop is a different action.

This is a source/intent explanation, not a native restart test run by this study.

Alice / whole map   /   Act outside

The call travels out. The dependency points in.

Call direction: runtime → injected model/service/Code implementation.
Dependency: alice-ai → alice. Code differs: the host's HostCodeRunner implements the runtime interface and adapts to alice-code; that runner has no alice dependency.

To use a service: discover the exact Integration → dispatch under Grants → host-mediated credential use → concrete adapter → durable result. An imported package grants no independent authority.
