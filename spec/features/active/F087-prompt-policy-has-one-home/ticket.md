# F087 · Prompt policy has one home

## Outcome

An operator can revise coordinator guidance without also maintaining the same sentences as test expectations. Handoff rules have one complete home, and a project's explicit role-model choices clearly take precedence over package defaults. The quality pass found duplicated authority across the shop manual, the communication register, phrase assertions, and the project board.

## Scope

- Start with the phrase inventories in `test/structure.test.ts`; separate assertions about prose wording from checks that prove the right guidance is packaged and delivered.
- Keep handoff content, its length ceiling, and the one-constraint-per-line instruction together in the shop manual rather than split across two prompt documents.
- State model-choice precedence in prose: the board owns explicit project choices, while the package provides defaults when no choice is recorded.
- Preserve the existing guidance on review, evidence, research authorization, and spec clarity while removing duplicate ownership, not the policies themselves.

## Out of scope

- Runtime model resolution, spawn argument transport, or a parser for board decisions.
- Choosing different models or changing when research, quality, or picture jobs run.
- Removing the changed-file counter, footer animation, or behavior tests.

## Acceptance

- A wording-only revision to the affected guidance does not require an equivalent edit to a phrase inventory in the structure suite.
- The handoff rule states its content, length ceiling, and constraint format in one place; the register no longer carries a contextless second instruction.
- The guidance unambiguously selects an explicit board model over a conflicting package fallback, without adding runtime state or Markdown parsing.
- Existing checks that a named-role spawn receives its preamble remain and pass.
- Existing template packaging and history-reference checks remain and pass.
